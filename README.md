# AI-Page-Translator — 整页翻译 · 图片文字翻译 · 页面 AI 阅读助手(浏览器扩展)

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

基于 OpenAI 兼容 API 的整页翻译扩展:**流式快翻 + 术语先行 + 流水线润色**,就地替换网页文本并保留结构;
外加一个**页内 AI 阅读助手**:把网页正文/大纲/图片当上下文,总结、记笔记、答疑、整理大纲、读图、截图翻译。
另外支持**图片文字翻译**(视觉模型 OCR + 覆盖渲染)。一套代码兼容 Chrome / Edge / Firefox(Manifest V3)。

## 特性

### 翻译

- **不漏译**
  - 影子 DOM(Web Components 站点)、同源 iframe、页面标题与 meta 描述
  - 属性文本:`placeholder` / `title` / `alt` / `aria-label`、按钮类 `input.value`
  - 折叠菜单 / 懒加载 / 隐藏 Tab:一样翻译(低优先级),曝光时已就绪
  - SPA 原地改字(`nodeValue` 改写)自动重翻
  - 超长段落按句物理切分,避免单次请求被模型截断
  - 模型丢哨兵/并段 → 稀疏解析 + 缺失段整块重试,最终仍未翻的段会**计数并显示**,可一键重试
- **快**
  - **批聚合**:小段攒批(默认 400ms / 20 段 / 8000 字符)一次请求,请求数常降到 1/5
  - **并发池 + 令牌桶限速**(默认 12 并发 / 8 请求每 1200ms),遇 429/5xx 自动降档退避重试
  - **视口优先**:IntersectionObserver 驱动,首屏先翻,滚动到哪翻到哪,不滚动时兜底翻完
  - **翻译缓存**:重复段落、重复访问零请求;缓存键含目标语言/模型/术语,切换不会串味
  - **术语先行**:开翻前 1 次小请求生成「术语表 + 风格指南 + 主题」,注入后续所有请求,一致性大幅提升
  - **流水线润色**:保留全页统一润色,但改成「每 N 块滚动触发 + 与快翻重叠执行」(总耗时≈1.2 轮而非 2 轮);
    正在阅读的段落会避让替换,且带版本号防旧润色回写
  - **同构重复块相邻**:列表/卡片渲染时措辞一致
- 直接替换文本节点,不破坏 DOM 结构 / 链接 / 样式;一键「恢复原文」
- 幂等:重复点「翻译此页」只翻新增内容
- **跳过不翻译**:`code/pre/script/style`、`translate="no"`、`.notranslate`、输入控件
- 自定义 API:API Key / Base URL / 模型(一键拉取模型列表);Key 留空可对接 Ollama 等本地服务

### 图片文字翻译

- 采集 `<img>`、`<picture>`、CSS `background-image`(可配最小尺寸、每页上限、仅视口内)
- 视觉模型一次拿到「文字框 + 原文 + 译文」,覆盖层渲染在图上,**字号自适应、可选中**
- **环带取色近似擦字**:纯色底图片用周边像素中位数填底再写译文;照片/渐变自动退化为半透明覆盖
- 结果缓存(图片内容 hash + 语言 + 模型),二次访问零消耗
- **模型不支持图片输入时会整页跳过并明确提示**,不会逐图重试浪费额度

### AI 阅读助手(页内面板 / Chrome 原生侧栏)

- 读取页面:正文分片(带 DOM 锚点)、标题大纲、表格、图片清单
- 六种模式:**总结 / 笔记 / 快速阅读 / 答疑 / 整理大纲 / 翻译选中**(选中文本自动带入)
- **上下文按需检索**:BM25-lite(中文 bigram)只把与问题最相关的片段送进模型,长页面也不爆上下文;
  页面资料整会话固定,历史只追加新片段(token 不随轮数膨胀)
- **引用可跳转**:回答里的 `[[n]]` 是按钮,点击滚动到对应段落并高亮
- **Markdown 开关**:面板/侧栏一键在「渲染 Markdown」与「原始纯文本」之间切换(设置里也有默认值)
- 附件:选中文本 / 网页图片(降采样后多模态发送)/ **截图翻译**(`captureVisibleTab`)
- 入口:页面右下角悬浮球、`Alt+Shift+A`、右键菜单、popup 按钮
- 安全:模型输出经过「先转义后白名单」渲染(禁内联 HTML、链接仅 http(s)/mailto),不会把模型输出当 HTML 执行

## 安装(开发模式)

- **Chrome / Edge**:`chrome://extensions`(或 `edge://extensions`)→ 开启「开发者模式」→「加载已解压的扩展程序」→ 选择 `src/` 目录
- **Firefox**:`about:debugging#/runtime/this-firefox` →「临时载入附加组件」→ 选择 `src/manifest.json`
  (Firefox 无 `sidePanel` API,助手会自动使用**页内面板**)

## 配置

设置页分六组卡片:连接 / 翻译 / 性能与缓存 / 行为 / 图片翻译 / 阅读与对话。要点:

| 配置 | 说明 |
|---|---|
| Base URL | OpenAI:`https://api.openai.com/v1`;DeepSeek:`https://api.deepseek.com`(自动补 /v1);Moonshot、通义千问兼容模式、one-api 中转均可;Ollama:`http://127.0.0.1:11434/v1`(Key 留空) |
| 模型名称 | 手动输入或点「获取模型列表」 |
| **应用推荐配置** | 老配置(并发 3、串行润色)会显得慢,一键切到推荐值:并发 12 / 限速 8·1200ms / 批 20 段·8000 字符 / 视口优先 / 缓存 / 术语先行 / 流水线润色 |
| 同时先翻首屏 | `视口优先` 开:先翻视口,滚动到哪翻到哪;关:按文档顺序全量并发 |
| 延迟兜底(ms) | 不滚动时,多久后把剩余内容也翻完(默认 3500) |
| 每请求字符 / 批聚合 | 单请求字符上限 / 攒批段数与字符上限;页面越小可把批调小 |
| 限速请求数 / 窗口 | 令牌桶参数,被限流时可调低 |
| 术语预分析 | 首次访问多 1 次小请求换全局一致性,强烈建议开 |
| 流水线润色 | 开=与快翻重叠(推荐);关=翻完再统一润色 |
| 视觉模型 | 图片文字翻译/读图用;留空则用对话模型(必须支持图片输入) |
| 面板形态 | 自动(Chrome 侧栏优先, Firefox 自动页内)/ 只用页内面板 / 只用侧栏 |
| Markdown 渲染 | 助手回复默认渲染 Markdown;可关成纯文本(面板里也有一键开关) |

填好后点「测试连接」验证,再「保存」。

## 使用

**翻译**:点工具栏图标 →「翻译此页」;`Alt+Shift+T` 也可。进度在 badge 与 popup;
完成行会显示「用时 · 请求数 · 缓存命中 · 未翻译段数(可重试)」。「恢复原文」还原,「停止」中止。

**翻译图片文字**:popup「翻译图片」/ `Alt+Shift+I` / 右键「翻译这张图片的文字」;用 popup「还原图片」清除覆盖层。

**AI 助手**:右下角悬浮球 / `Alt+Shift+A` / popup「AI 对话 · 读这一页」/ 右键选中文本。
用「总结」「笔记」等模式一键出结果;截图翻译用面板里的 📷;附件会以 chip 显示,可单独移除。

## 技术架构

```
┌────────────────────────── content script(每帧) ──────────────────────────┐
│ chunker   收集 Target(文本+属性 / 影子DOM / head) → 切块 → 稀疏解析 & 哨兵编解码 │
│ content   术语先行 → 缓存命中回填 → 视口调度 → 池/限速/批聚合 → SSE 流式回填    │
│           → 缺失段重试 → 流水线润色(rev 守卫 + 阅读避让)→ 指标上报           │
│ reader    正文/大纲/表格/图片抽取(带锚点)      rag  BM25-lite 检索            │
│ img/*     图片采集 → 视觉 OCR → 覆盖渲染(环带取色)                          │
│ panel/*   对话核心 + 页内 Shadow DOM 面板                                     │
└───────────────────────────────┬──────────────────────────────────────────┘
                    port / runtime 消息 │
┌───────────────────────────────▼──────────────────────────────────────────┐
│ background.js  fetch(SSE)/模型列表/取图/截图/缓存摘要/sidePanel/右键/快捷键   │
│ popup(翻译 · 图片 · AI 对话)   options(六组配置)   panel/sidepanel(侧栏容器)  │
└──────────────────────────────────────────────────────────────────────────┘
```

关键设计:

- **哨兵分块**:块内目标用 `⟦i⟧` 拼接成一次请求,响应按哨兵切回逐目标回填;
  解析器对「丢哨兵但行数吻合」的响应做行序修复,对缺段只重试缺的那部分
- **流式**:`stream:true` + SSE,段完整即回填;后台在端口断开时**中断上游请求**(停止不再烧额度)
- **缓存**:FNV+djb2 组合键(≈64 位,避免碰撞命中错译文),LRU + `chrome.storage.local` 持久化
- **上下文**:`system` 放整会话固定的页面资料(命中上游 prompt cache),每轮只追加新检索片段
- **渲染安全**:Markdown 先转义后白名单;面板/覆盖层用 Shadow DOM + `all:initial`,页面 CSS 干扰不到

## 本地开发

```bash
bash tests/run-all.sh                   # 一条命令跑全套(单测 + 4 个 e2e + UI 校验);也可 npm test
EXT_DIR=dist/chrome bash tests/run-all.sh   # 验证打包产物而不是 src/

node --test 'tests/*.test.mjs'          # 单测:chunker/pool/cache/markdown/rag/background/common
node tests/e2e.mjs                      # 翻译端到端(headless Chromium + mock,34 项断言)
node tests/e2e-image.mjs                # 图片文字翻译端到端(20 项断言)
node tests/e2e-chat.mjs                 # AI 助手端到端(29 项断言)
node tests/e2e-badge.mjs                # 进度/badge/lastProgress 回归(9 项断言)
node tests/verify-ui.mjs                # options/popup 元素·样式·a11y
node tests/options-model-sync.mjs       # 模型下拉同步回归
python3 tests/mock_server.py 18080      # OpenAI 兼容 mock server(不消耗额度)
./build.sh                              # 打包 dist/{chrome,edge,firefox}.zip
```

mock server 地址 `http://127.0.0.1:18080/v1`、Key 任意、模型 `mock-mini`(视觉用 `mock-vision-4o`),
测试页 `http://127.0.0.1:18080/` 覆盖影子 DOM / 属性文本 / 隐藏曝光 / 原地改字 / 超长段落 /
重复卡片 / 图片 / 视口与页脚标记,并提供 `/stats`、`/admin/reset|fail-once|vision-unsupported|slow` 便于断言。

e2e 断言只用两类可观测源:**页面 DOM 状态** 与 **mock 计数器**(内容脚本内部变量在隔离世界里读不到)。

跑测试的两条硬规矩(都踩过坑):

1. **不要并行跑两个 e2e**:它们共用 mock 的 18080 与计数器,互相 `reset`/改开关会造成"假失败"(脚本会检测并警告)。
2. **性能类断言要自测量**:先 `restore` 到干净页面、等计数器稳定再取基线,跑完再等稳定取终点,**不要复用上一轮累计计数** —— 若那一刻页面已翻完,本轮只发几个请求,术语/润色计数就是 0,看起来像随机失败。
   串行稳定性自检:`bash tests/stability-e2e.sh`(连跑 4 轮并打印每轮增量)。

## 隐私

- API Key 只存浏览器本地 `storage`,不同步云端
- 请求只发往你填写的 Base URL;开启助手时,**页面正文/大纲/图片描述**会作为上下文随请求发送
- 对话记录默认只在内存(可开「按网址保存」,仅本地)
- 遇到敏感页面请先关闭助手,或不要附加截图/图片

## 常见问题

- **改了代码 / 重新加载扩展后,弹窗按钮报「页面脚本没有响应…请刷新页面后重试」**:重新加载扩展只会影响之后打开的页面,已打开的标签页里跑的还是旧的页面脚本(内容脚本已成孤儿),任何按钮都会失败。**刷新页面(F5)即可**;用打包产物(`dist/`)时,重新打包后也要先重新加载扩展、再刷新页面。
- **点「重试」没反应 / 仍显示有未翻译段**:重试只针对「上一轮确认为失败」的段落;若页面结构变了或模型仍不稳定,可能仍有残留,可再点一次。修复说明:早期版本在「恢复原文」之后重试会被静默丢弃,现已修复。

## 已知限制

- 跨域 iframe 受浏览器安全策略限制无法注入;closed shadow root 无法访问
- `chrome://`、扩展商店等受保护页面无法注入
- 图片文字翻译依赖**视觉模型**,纯文本模型会被跳过(会提示)
- 截图的可用性取决于页面/系统权限(headless 下可能拿不到)
- 超大页面仍会消耗较多 token;被限流时池会自动降档,15 秒内不再被限流则并发逐级回升(不会一直慢到底),但整体仍会变慢
- 同一张图出现多次时默认每处都翻:识别结果按图片摘要缓存,重复处零额外模型成本(想只翻第一处可在设置里打开)
- 背景图扫描只看文档前若干元素(默认 5000,可在设置里调大;超大页面靠后的背景图需要调大才扫得到)
- 多个标签页同时翻译同一站点时,缓存落盘走「读-合并-写」,先后写入不会互相覆盖
- 助手单次问答的上下文按预算截断(默认 12000 字符 + 8 个检索片段),超长页面会优先给最相关的部分
- 极少数站点会用 `!important` 强改全局样式,我们的覆盖层已放进 Shadow DOM,基本不受影响
